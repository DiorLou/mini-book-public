# 调用表达式的求值过程

## 问题背景

学习 CS61A 的 Lecture 1 / Welcome 时，课程截图以 `add(2, 3)` 介绍调用表达式的结构，并给出 evaluation procedure。疑问是：为什么 `add`、`2`、`3` 都要先求值？求值和调用有什么区别？遇到嵌套调用时，究竟先做哪一步？

本页的基本规则与 `add(2, 3)` 来自课程截图；饮品店类比、嵌套调用和返回函数的代码是帮助理解的补充示例。

## 从一个具体例子开始

**调用表达式（call expression）**是要求调用某个函数的表达式，例如 `add(2, 3)`。下面的 Python 代码先导入示例需要的函数：

```python
from operator import add, mul

add(2, 3)  # 返回 5
```

**求值过程（evaluation procedure）**是把表达式变成值所遵循的步骤。表达式是写在代码中的形式，值是对它求值后得到的结果。

可以把一次调用想成饮品店制作饮品：先找到师傅，再准备材料，最后把材料交给师傅，取得成品。对应到程序，就是先确定函数、准备参数值，再执行调用、取得返回值。

## 调用表达式的结构：表达式与值分属两层

`add(2, 3)` 可以拆成三部分：

```text
add       (  2  ,  3  )
 ↑           ↑     ↑
operator    operand operand
```

**操作符表达式（operator expression）**是用来确定“调用谁”的表达式，这里是名字 `add`。这里的 operator 指调用中的位置和作用，不限于 `+` 这样的符号。

**操作数表达式（operand expression）**是用来产生传入值的表达式，这里分别是 `2` 和 `3`。对它们求值得到的值，就是本次调用的**实参（argument）**，即实际交给函数的数据。

| 代码中的表达式 | 求值得到的值 |
| --- | --- |
| `add` | 名字所绑定的加法函数 |
| `2` | 整数 `2` |
| `3` | 整数 `3` |
| 整个 `add(2, 3)` | 返回值 `5` |

函数本身也是值。因此，“对 `add` 求值”有明确含义：在当前环境中查找这个名字，取得它所绑定的函数。

```python
add        # 取得函数本身，不执行加法
add(2, 3)  # 调用函数，得到 5
```

数字字面量的求值更直接：`2` 求值得到整数 `2`。求值不一定包含算术运算，查找名字、取得字面量的值也都是求值。

## 两步求值规则：先准备，再应用

对于本页所讨论的 Python 普通位置参数调用，规则是：

1. 先对操作符表达式求值，再从左到右对各操作数表达式求值。
2. 将第一步得到的函数应用到已经得到的实参值上。

**应用（apply）**在这里就是实际调用函数，让它接收准备好的参数值并执行。

因此，`add(2, 3)` 的过程是：

```text
查找 add，取得加法函数
    ↓
对 2 求值，得到整数 2
    ↓
对 3 求值，得到整数 3
    ↓
调用加法函数，传入 2 和 3
    ↓
返回 5，作为整个调用表达式的值
```

“找到函数”和“执行函数”发生在不同的时刻。只有函数和参数值都准备好，才能进行这次调用。

## 嵌套调用：材料也可能需要先加工

下面是补充示例：

```python
add(2, mul(3, 4))  # 返回 14
```

外层调用的操作符表达式是 `add`，两个操作数表达式分别是 `2` 和整个 `mul(3, 4)`。`3`、`4` 属于内层调用，并非外层的两个独立操作数。

这就像师傅需要一份现做配料：配料尚未做好，外层制作就要等待。

1. 对外层的 `add` 求值，取得加法函数。
2. 对第一个操作数 `2` 求值，得到 `2`。
3. 对第二个操作数 `mul(3, 4)` 求值：
   - 查找 `mul`，取得乘法函数。
   - 依次对 `3` 和 `4` 求值。
   - 调用乘法函数，得到 `12`。
4. 外层参数值准备完成，分别为 `2` 和 `12`。
5. 调用外层加法函数，得到 `14`。

```text
add(2, mul(3, 4))
       └──12──┘
          ↓
add(2, 12)
          ↓
         14
```

这个图只是求值过程的示意，不表示 Python 实际修改了源代码文本。

这里体现了**递归求值（recursive evaluation）**：求值过程中遇到更小的调用表达式，就再次使用同一套规则；得到内层结果后，继续完成外层。它描述的是求值规则，不要求示例中有一个调用自身的递归函数。

### 为什么“先算最里面”不够准确

对于另一个补充示例：

```python
add(mul(2, 3), mul(4, 5))  # 返回 26
```

顺序是先取得外层 `add` 函数，再完整求左侧 `mul(2, 3)` 的值 `6`，再完整求右侧 `mul(4, 5)` 的值 `20`，最后执行外层加法调用，得到 `26`。

因此，外层函数先被找到，但外层调用最后才执行。“先算最里面”没有说明名字查找的顺序，也没有说明并列操作数从左到右求值的顺序。

## 操作符也可以是一个调用表达式

截图强调操作符和操作数都是表达式，因此它们都会求值得到值。下面的补充示例进一步说明：括号前面甚至不一定只是一个函数名。

```python
def choose_adder():
    return add

choose_adder()(2, 3)  # 返回 5
```

`choose_adder` 返回的是加法函数本身。最后一行可以这样拆分：

```text
choose_adder()    (2, 3)
└─ operator ─┘    参数部分
```

先对操作符表达式 `choose_adder()` 求值，得到加法函数；再依次对 `2` 和 `3` 求值；最后调用刚取得的函数，得到 `5`。

这个示例说明了规则的适用边界：操作符表达式必须得到可调用的对象，本页只讨论函数。任意数字并不能充当函数；同样，如果某个子表达式求值时抛出异常，也就无法继续按正常流程完成外层调用。

## 回到截图中的 evaluation procedure

截图的两条规则可以理解为：先把“要调用谁”和“要传入什么”都求出来，然后执行调用。

在 `add(2, 3)` 中，`add` 是产生函数的表达式，`2`、`3` 是产生实参值的表达式。第一步分别得到加法函数、整数 `2`、整数 `3`；第二步将这个函数应用到这两个整数上，整个表达式便得到值 `5`。

记住三个判断原则：

- 表达式与值要区分，函数本身也可以是值。
- 先求操作符，再从左到右求操作数，最后调用函数。
- 遇到嵌套调用就重复同一套规则，内层返回值成为外层所需的值。
